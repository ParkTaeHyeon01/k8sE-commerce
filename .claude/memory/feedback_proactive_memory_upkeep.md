사용자는 강의실/집 등 환경을 오가며 작업을 이어가기 때문에, 세션이 바뀌어도 일관된 맥락을 유지하는 것이 중요하다. 이를 위해 **요청받을 때만이 아니라, 작업 중 중요한 결정·방향 전환·계획 합의가 생길 때마다 알아서 메모리를 점검하고 갱신**해야 한다.

**Why**: 사용자가 "이런 기록 작업을 옮겨질 때마다 확인하면서 지속적으로 일관성 있게 반영되도록 해"라고 명시적으로 요청함. 이번 세션에서도 크롤링 대상이 G마켓→마켓컬리로 바뀌었는데 옛 메모에는 "쿠팡/G마켓"이 남아있었던 것처럼, 변경 사항을 그때그때 반영하지 않으면 다음 세션에서 잘못된 전제로 작업하게 됨.

**How to apply**:
- 다음과 같은 일이 생기면 그 즉시(대화가 끝나기 전에) 관련 메모리를 새로 쓰거나 갱신할 것:
  - 아키텍처/기술 스택 변경 (예: 크롤링 대상 변경, DB 선택 변경)
  - "~하기로 했다/~할 계획이다" 같은 합의·계획 (구현 전이라도 "방향 합의" 단계로 기록)
  - 기존 메모와 모순되는 새로운 사실 발견 시 — 바로 옛 메모를 찾아 갱신 (방치하지 말 것)
- 메모를 쓸 때 "구현 완료"인지 "방향만 합의, 구현 전"인지 상태를 명확히 구분해서 적을 것 (예: [[crawler-multi-instance-plan]]처럼 "아직 구현 전"을 명시)
- 세션 끝에 한 번에 몰아서 정리하지 말고, 결정이 나는 시점마다 바로바로 기록 — 대화가 길어지면 초반 맥락을 놓치기 쉬움
- [[feedback-workbook-friendly]]와도 맞물림: 메모리 자체가 "작업 이력의 워크북" 역할을 하므로 항상 최신 상태를 유지해야 함
